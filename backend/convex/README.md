# convex/

The deployment's code. Read `docs/design.md` §3 (data model), §4 (readiness) and §9
(concurrency) before adding anything here.

```
schema.ts        the one table registry — every table, nowhere else
_generated/      committed, regenerated by `vp run codegen`, never hand-edited
tests/           convex-test against the schema; `vp run @cairn/backend#test`
```

Where the first slice goes, once it is written:

| File | Holds |
|---|---|
| `issues.ts` | `create`, `list`, `claim`, `release`, `update`, `close`, `drop` |
| `journal.ts` | `append` — inserts only, never an update |
| `ready.ts` | the one hard query, §4, computed live |
| `show.ts` | `get`: an issue, epic or blocker by its public id, with its neighbourhood |
| `brief.ts` | `get`: the session-start report as data, §8 |
| `edges.ts` | `add`, `remove`; one direction stored, §3 |
| `epics.ts`, `blockers.ts`, `projects.ts` | their own tables' functions |
| `reconcile.ts`, `crons.ts` | `run` by hand, `sweep` on the cron, §7 |
| `lib/` | mechanism shared by the above: `ids`, `revision`, `actor`, `events`, `errors`, `views`, `inbox`, `readiness`, `guard`, `verification` |

Rules that hold from the first line:

- **A verb is one Convex function.** The CLI formats; it never decides.
- **A mutable write carries the `revision` it read.** A stale write is rejected with what
  changed, who changed it and when.
- **Journal entries are inserts.** Nothing updates one.
- **`epicId` is required** on every issue. There is no orphan state to represent.
